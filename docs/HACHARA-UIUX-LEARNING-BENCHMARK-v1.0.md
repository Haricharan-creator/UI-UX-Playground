# HACHARA UI/UX Learning Benchmark v1.0

## Status
LOCKED — authoritative learning benchmark for curriculum mapping and bundle design.

## Preservation rule
The benchmark does not replace, delete, restart, or duplicate the accumulated UI/UX lessons. Existing learning remains the source material. New structures must map to it.

## Learning progression
Understand → Strategize → Design → Implement → Test → Measure → Improve → Document/Handoff → Validate

## Knowledge domains
1. UX foundations — UI vs UX, user needs, business needs, goals, context, tasks, scenarios, pain points, friction, usability and experience quality.
2. Research — interviews, observation, behaviour, needs, goals, assumptions, evidence, synthesis, patterns and fact/assumption separation.
3. Problem definition — problem statements, root causes, framing, opportunities and evidence-led problem definition.
4. Information architecture — grouping, hierarchy, navigation, labels, findability, content structure and mental models.
5. User flows — entry points, tasks, decisions, branches, success, failure, recovery and completion.
6. Interaction design — affordances, actions, feedback, states, loading, empty, error, success, recovery, interruptions and user control.
7. Usability and heuristics — systematic evaluation, consistency, system status, error prevention, recognition/recall, control, feedback and cognitive load.
8. Visual design — hierarchy, typography, spacing, alignment, layout, composition, colour, contrast, emphasis and readability.
9. Responsive/mobile UX — screen adaptation, mobile constraints, touch interaction, prioritisation and experience adaptation.
10. Accessibility/inclusive design — accessibility, inclusive design, readability, contrast and broader user abilities.
11. Localization/internationalisation — language expansion, cultural/contextual adaptation and RTL layouts.
12. Stress/uncertainty/recovery — difficult situations, progressive disclosure, interruptions, uncertainty, feedback and recovery paths.
13. Content strategy — UX writing, labels, instructions, microcopy, error messages, clarity and cognitive-load reduction.
14. Design systems — tokens, components, reusable patterns, consistency and scalable product interfaces.
15. Prototyping and implementation — moving from concepts to interactive product experiences.
16. UX QA — inspect implemented product, compare against intended experience, identify differences, fix and retest.
17. Usability testing — tasks, observation, findings, behavioural evidence and iteration.
18. Metrics/measurement — UX metrics, usability-testing metrics and evidence-based improvement.
19. Documentation/handoff — specifications, communication, developer handoff, QA and lifecycle consistency.

## Capability distinction
Lesson completion ≠ understanding ≠ application ≠ real-world problem solving ≠ demonstrated capability.

## Capability model
Learn → Challenge → Build → Evidence → Review → Rework → Validate

V1 must be preserved. V2 changes must be recorded. Validation requires evidence.

## Product learning structure
Bundle → Module → Lessons → Skills → Practice → Real UX Challenge → Figma/Framer Task → Evidence → Review → Rework → Validation → Capability/Progress

## Core principle
Lessons are knowledge units. Bundles/modules organise learning. Challenges create application. Evidence demonstrates application. Review identifies gaps. Rework improves the work. Validation establishes demonstrated capability.

## Build rule
Future implementation must use this benchmark as the learning source of truth and must not invent a parallel curriculum that conflicts with the accumulated learning.
