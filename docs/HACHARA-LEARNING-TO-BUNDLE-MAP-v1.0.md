# HACHARA UI/UX Learning → Capability Bundle Map v1.0

## Purpose
Convert the accumulated UI/UX lessons into capability-based bundles without deleting, restarting, or duplicating the existing curriculum.

## Governing rule
Lessons remain the authoritative knowledge units. Bundles organize them into capability journeys. A bundle must reference existing lessons rather than recreate their content.

## Capability progression
1. Understand — research, users, context, evidence, synthesis, problem definition.
2. Strategize — goals, opportunities, information architecture, navigation, user flows.
3. Design — interaction design, wireframes, visual hierarchy, typography, layout, colour, components, prototypes.
4. Build/Implement — responsive/mobile behaviour, content, design systems, handoff and implementation awareness.
5. Evaluate — usability, heuristics, accessibility, inclusive design, UX QA, usability testing.
6. Measure — UX metrics, evidence, outcomes and learning from behaviour.
7. Improve — V1 findings, rework, V2 changes, validation and reflection.
8. Operationalize — documentation, handoff, reusable systems, project evidence and portfolio/history.

## Required bundle structure
Bundle → Module → Existing Lessons → Skill → Practice → Real UX Challenge → Figma/Framer Task → Evidence → Review → Rework → Validation → Capability Progress.

## Preservation rules
- Preserve every existing lesson and its source content.
- Preserve lesson identity/IDs when available.
- Do not renumber lessons merely to fit bundles.
- Do not create duplicate lessons to fill a bundle.
- If a lesson belongs to multiple capabilities, reference it rather than copying it.
- If mapping is uncertain, mark it as a mapping gap for review instead of guessing.

## Learning benchmark domains
UX foundations; research; synthesis; problem definition; user needs/goals; IA; user flows; interaction design; usability; heuristics; visual hierarchy; typography; layout/spacing; colour/contrast; responsive/mobile UX; accessibility/inclusive design; localization/internationalisation/RTL; content strategy/UX writing; design systems; prototyping; UX QA; usability testing; stress/uncertainty/recovery; metrics/measurement; documentation; handoff; iteration and validation.

## Evidence principle
Lesson completion proves exposure to knowledge. Practice demonstrates understanding. A real challenge demonstrates application. Evidence demonstrates execution. Review and rework demonstrate improvement. Validation demonstrates capability.

## V1/V2 rule
Original work (V1) must remain available. Review findings and changes must be traceable. V2 is an improvement layer, not a replacement that destroys evidence of the original decision.

## Implementation gate
Before declaring a bundle complete: verify lesson coverage, skill coverage, practice, challenge, evidence, review, rework, validation and progress mapping. Missing or ambiguous mappings become explicit source/mapping gaps.
