Accessible Keyboard Navigation

Learn how people who use keyboards, switch devices or other non-pointer input methods move through an interface, and how design decisions can make that journey predictable.

Learn

Every interactive path needs a usable route

Keyboard accessibility is not simply adding a visible focus ring. Interactive controls need to be reachable, ordered logically, operable with appropriate keys and understandable as the user moves through the interface.

Designer question: Can a person complete the core task without a mouse or touch, while always knowing where focus is and what action is available?
See

Keyboard navigation essentials

ReachabilityAll relevant interactive controls should be reachable through the supported keyboard path.
Logical orderFocus should follow a meaningful sequence that matches the task and visual structure.
Visible focusMake the current focus location clearly distinguishable.
Key behaviourDefine expected activation and navigation keys for the component pattern.
No trapsUsers should be able to enter and leave interactive regions without becoming stuck.
ContextOpening menus, dialogs and dynamic content should preserve understandable focus context.

Apply

Keyboard audit in Figma or Framer

Task

Choose a key flow such as sign-in, checkout or navigation. Draw the expected focus order and identify every interactive component.

Deliver

Prototype focus states and document activation, escape/close, menu and dialog behaviour where relevant. Identify any possible focus traps.

When implemented, run the flow with a keyboard and compare the actual path with your intended task order.
