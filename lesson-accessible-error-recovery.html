Accessible Error Recovery

Learn how to design errors as recoverable moments: preserve user effort, explain what happened, point to the problem and make the next action clear.

Learn

An error is part of the journey

People make mistakes, systems fail and information can become invalid. Accessible UX does not merely announce failure; it helps the person understand the situation and continue without unnecessary loss of work.

Designer question: When something goes wrong, can the person understand what happened, locate the affected item, fix it and continue with minimal re-entry?
See

Error-recovery essentials

PreventPrevent avoidable errors when the constraint is known and doing so does not reduce user control.
ExplainUse specific, understandable language instead of vague failure messages.
LocateMake it clear which field, step or action needs attention.
RecoverGive a concrete next action or correction path.
PreserveProtect entered information and completed work where possible.
ConfirmCommunicate successful recovery so the person knows what changed.

Task

Choose a form or important workflow. Design at least one validation error, system failure and recovery/success state.

Deliver

Show the exact message, affected control, preserved data, recovery action and resulting success state. Document keyboard/focus behaviour where relevant.

Test the implemented flow with realistic invalid inputs and interruptions. Check that recovery does not create a new barrier.
