Accessibility is part of UX quality

Accessibility is not a final compliance check. It influences structure, content, colour, interaction, focus, motion, media and responsive behaviour from the beginning of a design.

Designer question: What barriers could prevent someone from perceiving, understanding or operating this experience, and how can the design remove or reduce them?

Core accessibility considerations

PerceivableProvide alternatives and sufficient distinction for important information.
OperableSupport keyboard and other input methods where relevant.
UnderstandableUse clear structure, labels, instructions and predictable behaviour.
RobustDesign with semantic structure and assistive technology compatibility in mind.
FocusMake current keyboard focus visible and logical.
ContrastCheck text and meaningful UI elements for sufficient contrast.

Which approach best reflects accessibility-first thinking?

Apply

Accessibility review in Figma or Framer

Task

Choose one flow and review hierarchy, labels, focus order, contrast, touch targets, keyboard interaction, motion and content clarity.

Deliver

Create an accessibility issue list with evidence, affected interaction, potential impact and a proposed design exploration. Validate with appropriate tools and users where possible.

Do not assume a single automated check proves accessibility. Combine design review, implementation testing and user evidence where practical.
