# HACHARA User Manual

HACHARA is a UI/UX learning and creation workspace. It is designed as a continuous loop: **Learn → Think → Ideate → Develop → Test → Correct → Rework → Build → Share → Reflect**.

## 1. Choose your interface

Open `ui-options.html` to choose between:

- **Classic HACHARA Workspace** — the existing navigation-rich workspace and all preserved tools.
- **Modern HACHARA Workspace** — the dashboard-oriented interface with the HACHARA Loop, progress, ideas, quick actions and contextual learning entry points.

The preference is stored locally in the browser. The interface choice is a presentation preference; it is not a second product or a second project database.

## 2. Where should I start?

- **Learn** — understand a UX/UI concept.
- **Think & Ideate** — frame a problem and explore possibilities.
- **Research** — define objectives, questions, evidence and findings.
- **Develop / Builder** — turn requirements and ideas into design work.
- **Test / Review** — inspect screens, identify issues and record decisions.
- **Project Workspace** — keep project context and progress together.
- **Import / Export** — move project data in and out when needed.
- **User Manual** — return here whenever you are unsure what to do next.

## 3. How to use examples

Do not learn a principle only from its definition. For important concepts, use the pattern:

**Concept → Real-world scenario → Example screen → What to notice → Principle → Why it matters → Better alternative → Try it yourself → Test the result.**

Images or annotated screen illustrations should be used when they communicate hierarchy, spacing, navigation, interaction, layout or visual comparison faster than text.

## 4. Design review method

Use this sequence when reviewing a screen:

1. State the user goal.
2. Observe what is actually visible.
3. Connect the observation to a UX/UI principle.
4. Explain the user impact.
5. Record severity or priority when appropriate.
6. Propose a change.
7. Test the change.
8. Record what was learned.

## 5. Project continuity

The existing HACHARA application uses browser-local storage for many working records. Do not assume a UI change means a data reset. The two UI options are intended to sit on top of the same product direction and should not silently delete or replace project work.

## 6. Safe change principle

Existing functionality is the baseline. New UI options, examples and documentation should be added without removing existing tools or changing their meaning unless that change is explicitly approved.

## 7. Troubleshooting

If a feature appears missing:

1. Return to the Classic Workspace.
2. Open the User Manual.
3. Check the relevant module from the navigation.
4. Confirm that the browser is using the same HACHARA origin so browser-local data remains available.
5. If the issue persists, record the screen, action and expected result before changing anything.
