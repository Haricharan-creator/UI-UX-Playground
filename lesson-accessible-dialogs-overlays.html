Accessible Dialogs & Overlays

Learn how to design modals, dialogs, drawers, sheets and other overlays so people can understand the interruption, move through it, complete or cancel the task, and return to the right place.

Learn

An overlay changes the user's context

A dialog can temporarily interrupt the underlying page. Good design makes that change explicit, gives the person a clear task and exit path, and restores context when the overlay closes.

Designer question: When an overlay opens, does the person know why it appeared, where interaction should happen, how to close it, and where they return afterward?

Dialog essentials

PurposeGive the dialog a clear title and explain the action or decision.
Focus entryMove interaction to the appropriate control when the dialog opens.
Focus boundaryPrevent confusing interaction with background content while the modal task is active.
ExitProvide an understandable close or cancel path and support appropriate input methods.
Destructive actionsMake consequences clear and avoid ambiguous confirmation choices.
Return contextAfter closing, restore focus/context to a sensible location.

Apply

Design a dialog system in Figma or Framer

Task

Choose a confirmation, form or destructive-action dialog. Map opening, focus entry, interaction, validation, cancel, close and return context.

Deliver

Create the component variants and interaction states. Annotate expected keyboard behaviour, close behaviour and what happens to the underlying page.

Validate the implemented experience with keyboard and appropriate assistive-technology testing when available. A visual prototype alone cannot prove focus management.
