Heuristic Evaluation

Learn how to inspect an interface against established usability principles, describe concrete evidence, and turn findings into actionable design recommendations.

Learn

Evaluate systematically

A heuristic evaluation is an expert review of an interface against usability principles. It is useful for finding potential problems quickly, but it does not replace observing real users.

Designer question: What exactly happened in the interface, which usability principle does it conflict with, who may be affected, and what evidence supports the finding?
See

Useful heuristics to remember

VisibilityKeep important system status and feedback understandable.
MatchUse language and concepts familiar to users.
ControlSupport undo, escape and recovery where appropriate.
ConsistencySimilar things should behave and appear consistently.
Error preventionReduce opportunities for avoidable mistakes.
RecognitionReduce unnecessary memory load by making options visible.
Example finding: After submitting a form, no visible confirmation appears. Evidence: the user receives no immediate status signal. Recommendation: provide a clear success state and explain what happens next.

Apply

Audit a screen in Figma or Framer

Task

Choose one screen and identify at least five potential usability issues using recognised heuristics.

Record

For each issue capture evidence, heuristic, affected user/task, severity rationale and recommendation.

Keep finding, evidence and recommendation separate. Mark uncertain observations as hypotheses rather than facts.
