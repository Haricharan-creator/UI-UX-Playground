53. Plain Language for UX

Write so people can understand the message quickly and know what to do next.

LEARN

Clarity beats cleverness

Use familiar words, concrete actions and concise sentences. Match language to the user's task and knowledge. Avoid unnecessary jargon, vague labels and internal product terminology.

Designer question: Could a first-time user understand this message without knowing our internal language?

SEE
  • Prefer specific action labels such as “Save changes”.
  • Put the important information first.
  • Explain unfamiliar terms when they are necessary.
  • Use consistent terminology across the product.
  • Write errors around recovery, not blame.
CHECK

Which label is clearer?

APPLY — FIGMA / FRAMER

Audit ten labels or messages in an existing screen. Rewrite vague, technical or passive wording. Put the revised copy into your prototype and check whether the UI still fits longer text.

Loop: V1 → Copy review → V2 → Readability check → Reflect
