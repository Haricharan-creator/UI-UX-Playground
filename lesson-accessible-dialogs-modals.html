Accessible Dialogs & Modals

Learn how dialogs, confirmations and modal workflows should manage focus, context, closure and recovery so people can complete the task without becoming disoriented.

Learn

A modal creates a temporary context

When a dialog appears, users need to understand why it opened, what action is expected and how to leave it. The underlying page should not compete with the temporary task.

Designer question: When the dialog opens and closes, can the user understand the new context, reach its controls, exit predictably and return to the right place?
See

Dialog accessibility essentials

PurposeGive the dialog a clear title and explain why it is open.
Initial focusPlace focus in an appropriate starting location for the task.
Focus containmentKeep keyboard focus within the active modal context when appropriate.
Close pathProvide a clear close or cancel action and predictable keyboard behaviour.
BackgroundPrevent inactive background content from confusing the active interaction.
Return focusAfter closure, restore focus to a logical originating control or context.

Task

Deliver

Prototype the complete state transition and document what happens for confirm, cancel, close and keyboard escape where appropriate.
